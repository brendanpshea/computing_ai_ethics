# Computing and AI Ethics

**Brendan Shea, PhD — Rochester Community and Technical College**

A complete, open-access textbook on the philosophical, social, and ethical dimensions of information technology and artificial intelligence. First taught at RCTC in Spring 2026.

**[Read the textbook online](https://brendanpshea.github.io/computing_ai_ethics/)**

No prior background in philosophy or computer science is required.

**Lecture slides** are written in LaTeX (Beamer) and are the primary authored materials. **HTML readings** expand them into full prose with definition boxes, key-thinker profiles, argument boxes, case studies, and thought questions. **Quizzes** are auto-graded in the browser — 20 questions per chapter, mixing multiple choice, select-all-that-apply, and matching; progress is saved locally. **Word downloads** (beta) are generated from the readings via Pandoc, with Mermaid diagrams pre-rendered.

Course documents — syllabus, final project, final exam, and a glossary — are in [`docs/`](docs/).

## Repository layout

```
latex/      Lecture sources (.tex) and the shared preamble
html/       Chapter readings, quizzes, and their CSS/JS; quiz banks in quiz-data/
images/     Figures and portraits, all public domain or openly licensed
docs/       Syllabus, assignments, glossary, and authoring/build guides
scripts/    Build and check tooling
refs.bib    One bibliography, shared by the LaTeX slides and the HTML readings
index.html  Landing page for the published site
PDFs/       Built slides — NOT tracked in git (see below)
```

**`main` is source-only.** The compiled lecture PDFs are deliberately *not* committed — they are large binaries that change on every edit, and keeping them in history would bloat every clone. They are built on demand and published to the `gh-pages` branch, which is force-pushed as a single commit each deploy so it never accumulates history either.

The practical consequence: **PDF links only work on the published site**, not when browsing this repository on GitHub. Run a build if you want them locally.

`refs.bib` is shared. `\parencite{key}` in a `.tex` file and `<cite data-key="key">` in a chapter resolve against the same entries, so a source added once is available to both.

## Building

**Slides** (needs TeX Live with Beamer, metropolis, plex, tcolorbox, fontawesome5, and biber):

```bash
./scripts/build-pdfs.sh          # all 12 decks → PDFs/
./scripts/build-pdfs.sh 4        # just lecture 4
```

```powershell
.\build.ps1                      # Windows equivalent, with incremental + parallel builds
```

Each deck runs `pdflatex → biber → pdflatex → pdflatex`; the build fails loudly on undefined citations rather than shipping `[?]` marks. Details in [`docs/BUILD.md`](docs/BUILD.md).

**Word exports** (needs Pandoc and Node):

```bash
npm install
node scripts/build-docx.js       # all chapters → docx/
node scripts/build-docx.js ch03  # just chapter 3
```

**Checking the chapters** before publishing:

```bash
python3 scripts/check-chapters.py
```

This enforces the mechanical parts of [`docs/CHAPTER_GUIDELINES.md`](docs/CHAPTER_GUIDELINES.md) — citation keys that resolve, alt text, table captions and header scopes, working anchors and chapter links, heading order, tag balance, and the per-chapter element minimums. It says nothing about prose or facts; **quotations still have to be verified by hand.**

**Working on the chapters locally** requires a web server, because `cite.js` uses `fetch()` to load `refs.bib`:

```bash
python3 -m http.server 8000      # then open http://localhost:8000/html/ch01_history.html
```

**Publishing:**

```powershell
.\deploy-pages.ps1               # builds the PDFs, then force-pushes the site to gh-pages
```

GitHub Pages serves the `gh-pages` branch from the repository root (Settings → Pages → Deploy from a branch).

## Authorship and tools

The lecture slides were written by Brendan Shea in LaTeX and are the primary authored materials. The HTML chapter readings were derived from those slides with assistance from large language models — primarily [Claude (Anthropic)](https://claude.ai). All content has been reviewed and edited by the author.

A note for anyone adapting these materials: LLM-assisted drafting is unusually good at producing *plausible* citations and quotations. A July 2026 accuracy pass found several quotations that had been attributed to real thinkers but could not be traced to anything they wrote, along with ideas credited to the wrong person. If you reuse this material, treat direct quotations as unverified until you have checked them against the source. The reasoning is spelled out in [`docs/CHAPTER_GUIDELINES.md`](docs/CHAPTER_GUIDELINES.md) §5.7.
